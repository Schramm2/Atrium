# External Design Reference Review

Read this file when an external `DESIGN.md`, reference site, screenshot, generated draft, or reference library shapes the target contract.

## Record the source

Capture the URL or artifact path, product or theme name, version when known, retrieval date, and the exact ideas adopted.

## Extract portable primitives

- Token anatomy and semantic scales
- Typography roles and fallbacks
- Spacing, radius, elevation, and component scales
- Theme and surface variants
- Hover, focus, active, disabled, error, loading, and empty states
- Motion, accessibility, and content coverage
- Export, lint, theme, and component constraints
- Concrete review rules that an agent can prove against a screen

## Ground the target contract

Use the reference for structure, vocabulary, and prompts. Derive the target palette, fonts, radii, motion, voice, component values, and surface rules from the target repository and Matthew's direction. Mark unsupported choices as open questions.

Treat URL-generated, screenshot-derived, image-to-code, and reference-library drafts as provisional until repository evidence or explicit direction confirms them.

Complete the review when every adopted idea names its source and target-repo consequence, and every unsupported value has been removed or recorded as an open question.
